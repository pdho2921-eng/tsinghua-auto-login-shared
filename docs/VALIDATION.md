## 0.1.3 VirtualBuddy 实机诊断与修复

- 实际操作用户已安装 Chrome 和助手的虚拟机，检查表单就绪状态及扩展提交标志。诊断只读取字段是否为空、按钮是否可用和流程状态，不读取、记录或传输真实密码；现有钥匙串凭据未改动。
- 统一认证页面已加载完成，登录处理程序已存在，但可选字段 `#fingerGenPrint3` 持续为空。0.1.2 因此一直等待，未产生提交。手动点击同一学校表单能进入二次验证，证明该字段非空不是学校接受登录的必要条件。现已移除这一扩展额外条件，保留页面加载、按钮处理程序、文档及表单复查和单次提交。
- 虚拟机设置页显示自动模式开启，存储中却没有 `automatic` 字段。设置页默认开启，后台与取用后检查默认关闭，导致从钥匙串恢复账号后行为不一致。现统一为开启；用户明确保存的关闭值仍保持关闭。
- 两项缺陷均先以旧逻辑复现回归失败，再应用修复通过。五个浏览器场景覆盖指纹持续为空、资源加载延迟、统一认证按钮处理程序延迟、邮箱按钮延迟和提交后慢响应；均只提交一次。71 项行为检查及完整隔离浏览器回归通过。
- 已更新虚拟机 Chrome 实际加载的下载目录扩展，管理页确认 0.1.3；助手仍为 0.1.1，连接正常。没有重装助手或重新保存账号密码。
- 网络学堂：打开学校认证页后，无需点击图标或登录按钮，自动进入课程页；流程记录为 `manual: false`、`steps.submit: true`、`status: done`。此前新虚拟机出现的二次验证由用户完成；按用户确认，后续到达二次验证可视为自动提交环节通过，但不等同于进入网站主页。
- 信息门户：真实认证表单自动提交，记录为 `manual: false`、`steps.submit: true`；随后当前网络转到 WEBVPN 登录页。WEBVPN 属于另一应用，扩展未提交其表单；本次不记为门户主页登录成功。
- 邮箱：打开带虚拟过期会话标记的学校邮箱地址，出现真实服务器过期页；刷新后自动恢复到邮箱主页。流程记录为 `manual: false`、`steps.mail-relogin: true`、`steps.submit: true`、`status: done`。测试前通过设置页关闭再开启总开关，清除门户未完成流程的冷却；最终自动模式与三个站点开关均保持开启。
- 临时诊断页面仅用于虚拟机传输本项目扩展及不含凭据的诊断文字，不接收网页或密码数据。检查完成后关闭临时服务。

## 0.1.2 虚拟机反馈与修复

- 用户反馈三个网站均能稳定填充、自动登录偶发成功，手动点击可以成功；单标签页与多标签页均会出现。0.1.2 这一轮没有操作用户虚拟机或读取其中的凭据。
- 在隔离 Chromium 中延迟页面加载和按钮初始化，旧代码出现“点击发生时网页尚未就绪”，计数为 1；在多标签页回归中，前一页已在后台登录成功，后一页的提交仍被拒绝。两个用例均先失败，再应用修复通过。
- 当时对学校公开登录源码进行只读检查：统一认证存在异步初始化字段，Coremail 在渲染后通过 jQuery 绑定按钮。新检查等待这些条件就绪后才允许单次提交。
- 在独立的全新浏览器资料中打开真实统一认证和邮箱登录页，仅运行相同的只读就绪检查；两页均能正常判定就绪。未输入凭据、点击登录或发送登录请求。这确认了当前真实页面能被新检查识别，但不代表已完成真实登录。
- 新增四种浏览器场景：资源慢加载、全新浏览器中的异步初始化、邮箱按钮晚绑定、提交后慢响应；均确认没有过早点击，且只有一次提交。既有设置、预填替换、人工编辑取消、站点开关、邮箱过期页及错误预览检查通过。

## 2026-11-12 邮箱与独立开关复测

- 原因一：设置页将邮箱标为“可选”，但旧流程没有使用清华账号的默认规则，因此未单独保存邮箱时自动流程不启动，工具栏转去设置。现已按用户确认的规则修正，邮箱显示“使用清华账号”；复制和眼睛按钮仍只处理当前输入。
- 原因二：旧邮箱地址刷新后会出现服务器返回的独立过期页，结构为 `.sysMessage`，只有“确定”按钮，与应用内 `.u-dialog` 双层弹窗不同。已用公开虚拟会话响应核对结构，补充严格识别及回到邮箱首页的路径，并加入先失败、后通过的回归测试。
- 原因三：工具栏此前把无法识别的网站默认当作网络学堂。现在设置页、预览页及不支持的网站均不导航；已在实际设置页点击图标确认保持原页。
- 实际 Chrome 仅重新加载共享版扩展和旧过期邮箱标签页；没有输入或查看密码。页面自动回到邮箱首页后进入收件箱，工具栏显示“已进入学生邮箱”。随后再次点击工具栏，仍在该标签页回到邮箱并显示成功；这验证了自动过期恢复及手动入口。
- 设置页三个网站开关已显示，默认保持开启。逐站关闭、总开关关闭、明确手动执行、待提交及正在取用时取消由自动化检查覆盖；没有为了测试退出真实账号或改变用户的最终开关选择。
- 同步安装副本及分享包；本机助手仍为 0.1.0，未更换二进制或修改现有钥匙串凭据。扩展及分享包版本保持 0.1.1。

开发中修正了两项问题：ZIP 使用明确的 UTF-8 文件名，避免解压后的中文目录乱码；更新密码时仅更新数据并保留授权，避免每次保存都重新修改钥匙串访问控制。

## 首次试用流程与操作成本

1. 解压安装包，双击一次安装文件。
2. 在 Chrome 扩展页开启开发者模式，加载已安装的 `extension` 文件夹。
3. 在设置页保存所需账号密码，刷新对应网站。

无需安装 KeePassXC、浏览器密码管理插件、命令行开发工具，无需手动编译或注册开机启动项。以上是当前交付流程，**实际完成时间和点击次数尚未由新使用者实测**。从网络下载产生的系统确认也尚未计入。

## 试用时的隔离

共享版与个人版使用不同的扩展身份、安装目录和钥匙串服务。试用时应手动关闭个人版的浏览器扩展，防止二者同时操作同一网页；个人版文件、密码库和启动配置保持原样。开发操作没有新增或更改用户的真实凭据；后续凭据更新由用户自行完成。
