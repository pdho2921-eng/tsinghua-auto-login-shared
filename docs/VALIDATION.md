- 原因一：设置页将邮箱标为“可选”，但旧流程没有使用清华账号的默认规则，因此未单独保存邮箱时自动流程不启动，工具栏转去设置。现已按用户确认的规则修正，邮箱显示“使用清华账号”；复制和眼睛按钮仍只处理当前输入。
- 原因二：旧邮箱地址刷新后会出现服务器返回的独立过期页，结构为 `.sysMessage`，只有“确定”按钮，与应用内 `.u-dialog` 双层弹窗不同。已用公开虚拟会话响应核对结构，补充严格识别及回到邮箱首页的路径，并加入先失败、后通过的回归测试。
- 原因三：工具栏此前把无法识别的网站默认当作网络学堂。现在设置页、预览页及不支持的网站均不导航；已在实际设置页点击图标确认保持原页。
- 实际 Chrome 仅重新加载共享版扩展和旧过期邮箱标签页；没有输入或查看密码。页面自动回到邮箱首页后进入收件箱，工具栏显示“已进入学生邮箱”。随后再次点击工具栏，仍在该标签页回到邮箱并显示成功；这验证了自动过期恢复及手动入口。
- 设置页三个网站开关已显示，默认保持开启。逐站关闭、总开关关闭、明确手动执行、待提交及正在取用时取消由自动化检查覆盖；没有为了测试退出真实账号或改变用户的最终开关选择。
- 同步安装副本及分享包；本机助手仍为 0.1.0，未更换二进制或修改现有钥匙串凭据。扩展及分享包版本保持 0.1.1。

开发中修正了两项问题：ZIP 使用明确的 UTF-8 文件名，避免解压后的中文目录乱码；更新密码时仅更新数据并保留授权，避免每次保存都重新修改钥匙串访问控制。

## 首次试用流程与操作成本

1. 解压安装包，双击一次安装文件。
2. 在 Chrome 扩展页开启开发者模式，加载已安装的 `extension` 文件夹。
3. 在设置页保存所需账号密码，刷新对应网站。

无需安装 KeePassXC、浏览器密码管理插件、命令行开发工具，无需手动编译或注册开机启动项。以上是当前交付流程，**实际完成时间和点击次数尚未由新使用者实测**。从网络下载产生的系统确认也尚未计入。

## 试用时的隔离

共享版与个人版使用不同的扩展身份、安装目录和钥匙串服务。试用时应手动关闭个人版的浏览器扩展，防止二者同时操作同一网页；个人版文件、密码库和启动配置保持原样。开发操作没有新增或更改用户的真实凭据；后续凭据更新由用户自行完成。
