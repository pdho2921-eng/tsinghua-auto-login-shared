## 0.1.1 实际使用复测

- 已将用户在解压目录中修改的两个 HTML 文件纳入源文件，并同步 README 的安装和图标说明。
- 日常 Chrome 已重新加载 0.1.1。该浏览器实际加载源目录的扩展，Library 中安装的扩展副本也已同步；本机助手保留 0.1.0，协议相同，连接成功，现有钥匙串条目未改动。
- 使用原学校认证地址复测时，自动流程越过了此前的预填匹配拦截，提交后页面显示保存的别名；学校返回“您的用户名或密码不正确，请重试！”。未重复尝试、未读取或记录真实密码。这说明原匹配拦截已解除，但不能据此确认凭据正确或整个登录成功。
- 随后用户在测试标签页组更新账号密码，并确认现在可以正确登录。回看该标签页时，实际页面为信息门户“我的工作台”，扩展工具栏显示“已进入信息门户”。此结果证明当前测试页已登录成功；没有观察用户更新凭据的具体操作，不将其等同于三个网站均已完成无人操作的完整验收。
- 实测另发现学校拒绝页位于 `/do/off/ui/auth/login/check`。已将它作为只读结果页识别，显示醒目错误提示，禁止在此页面取用或再次提交凭据；以对应虚拟页面及回归用例验证。
- 待用户确认的界面和状态另见 [界面检查清单](界面检查清单.md)。
- 后续界面复核：复制按钮增加明确的来源文字；连接处与页尾分别标明助手／扩展版本；关闭标签页提示移入“3 · 开始使用”，与帮助标题、正文均采用 13px。新增 24 种错误提示预览，关闭／重新显示、桌面和窄窗口已检查；预览复用真实提示代码，浏览器检查确认未产生本机助手请求。

开发中修正了两项问题：ZIP 使用明确的 UTF-8 文件名，避免解压后的中文目录乱码；更新密码时仅更新数据并保留授权，避免每次保存都重新修改钥匙串访问控制。

## 首次试用流程与操作成本

1. 解压安装包，双击一次安装文件。
2. 在 Chrome 扩展页开启开发者模式，加载已安装的 `extension` 文件夹。
3. 在设置页保存所需账号密码，刷新对应网站。

无需安装 KeePassXC、浏览器密码管理插件、命令行开发工具，无需手动编译或注册开机启动项。以上是当前交付流程，**实际完成时间和点击次数尚未由新使用者实测**。从网络下载产生的系统确认也尚未计入。

## 试用时的隔离

共享版与个人版使用不同的扩展身份、安装目录和钥匙串服务。试用时应手动关闭个人版的浏览器扩展，防止二者同时操作同一网页；个人版文件、密码库和启动配置保持原样。开发操作没有新增或更改用户的真实凭据；后续凭据更新由用户自行完成。
